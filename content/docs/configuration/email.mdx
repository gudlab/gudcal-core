<Callout type="success" twClass="mt-0">
  GudCal uses Resend for transactional emails including magic-link login, booking confirmations, and password reset flows.
</Callout>

## Steps

<Callout type="note">
  The email configuration follows the [Resend](https://resend.com/) documentation.
  You can also refer to the official Auth.js docs
  [here](https://authjs.dev/getting-started/installation#setup-environment) for more details.
</Callout>

<Steps>

### Create an account

If you don't have an account on Resend, sign up [here](https://resend.com/signup).

### Create an API key

After signing in to Resend, create your first API key.

Copy/paste it in your `.env` file:

```js
RESEND_API_KEY = re_your_resend_api_key;
```

### Configure sender domain

For production, add and verify your domain in Resend to send emails from your own address (e.g. `notifications@gudcal.com`).

Set `EMAIL_FROM` to that verified mailbox. Booking guest mail uses
`HostName via GudCal <mailbox>` so Gmail shows the host name and the ICS
`ORGANIZER` mailbox matches `From`. The default is
`GudCal <noreply@mailman.gudcal.com>`.

Confirmed guest mail attaches a `METHOD:REQUEST` ICS. Cancel of a confirmed
booking attaches `METHOD:CANCEL`. Pending bookings do not get an ICS, including
pending cancel (there was never a prior `REQUEST`).

Reschedule of a confirmed booking sends two guest emails: `CANCEL` for the old
UID, then `REQUEST` for the new UID. Some calendar clients ignore `CANCEL`
when both files share one message.

ICS attachments use a Base64 `content` string plus `contentType`, the shape
Resend's JSON API documents. A Node `Buffer` is not that shape.

</Steps>
