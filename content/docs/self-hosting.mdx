## Prerequisites

- **Node.js** 18.17 or later (20.x from `.nvmrc` is what CI uses)
- **PostgreSQL** 14 or later (Neon, Supabase, or self-hosted)
- **pnpm** package manager

## Quick Start

1. Clone the **public** repository:

```bash
git clone https://github.com/gudlab/gudcal-core.git
cd gudcal-core
```

2. Install dependencies:

```bash
pnpm install
```

3. Copy the environment file and configure it:

```bash
cp .env.example .env.local
```

4. Set up the database:

```bash
pnpm prisma generate
pnpm prisma db push
```

5. Start the application:

```bash
pnpm build
pnpm start
```

Docker Compose is usually faster for a first run — see the README.

## Environment Variables

These are the required environment variables for self-hosting:

| Variable | Description |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string |
| `NEXTAUTH_SECRET` / `AUTH_SECRET` | Random secret for session encryption |
| `NEXTAUTH_URL` | Your deployment URL (e.g. `https://cal.example.com`) |
| `NEXT_PUBLIC_APP_URL` | Same as NEXTAUTH_URL |
| `ENCRYPTION_KEY` | 32-byte hex key (64 hex chars) for encrypting calendar tokens |

### Optional Variables

| Variable | Description |
|---|---|
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google login |
| `RESEND_API_KEY` | Transactional email |
| `STRIPE_*` | Cloud billing only — omit for self-host |
| `GOOGLE_CALENDAR_CLIENT_ID` / `SECRET` | Google Calendar sync |
| `CRON_SECRET` | Reminder cron endpoint |
| `NEXT_PUBLIC_IS_SELF_HOSTED` | Set to `true` on your instance |

## Self-Hosted vs Cloud

Set `NEXT_PUBLIC_IS_SELF_HOSTED=true`. That **removes hosted plan caps** on core scheduling (event types, calendars, availability, organizations). It does **not** turn your box into GudCal Cloud.

| | Your self-host (own org) | gudcal.com |
|---|---|---|
| Event types, bookings, calendars | Uncapped | Free / Pro / Team limits |
| Organizations | Uncapped | **Team** ($20/mo) |
| Hosted MCP at `gudcal.com/api/mcp` | n/a | **Team** |
| `/api/mcp` on *your* URL | Ships in this source; BSL allows it for your org | Same codebase |
| Analytics, custom domains | Hosted extras | Pro / Team |

Do not use a self-host to sell scheduling to other companies. That is the BSL restriction.

## Generating an Encryption Key

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## Reverse Proxy

If you run GudCal behind a reverse proxy (nginx, Caddy, etc.), make sure to:

- Forward the `Host` header
- Set `X-Forwarded-Proto` to `https`
- Set `X-Forwarded-For` to the client IP
- Configure WebSocket passthrough if needed
